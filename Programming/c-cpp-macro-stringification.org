* 字符串化宏变量

在 C/C++ 中， *字符串化宏变量* （通常指把宏参数变成字符串字面量）主要靠预处理运算符 =#= 。它会在传入的参数两端自动加上双引号，变成一个字符串常量。

** 基本用法

#+begin_src c
#include <stdio.h>

#define TO_STR(x) #x

int main() {
    printf("%s\n", TO_STR(hello world)); // 输出: hello world
    printf("%s\n", TO_STR(123 + 456));   // 输出: 123 + 456
    return 0;
}
#+end_src

注意： =#= 转换的是 *传入的源码文本/宏参数本身* ，不是运行时变量的值。比如 =int a = 10; TO_STR(a)= 得到的是 ="a"= ，不是 ="10"= 。

** 常见的坑/进阶：参数本身也是宏怎么办？

如果直接用 =#x= ，预处理器 *不会* 先展开 =x= 里的宏，而是直接把宏名变成字符串。
想先展开宏再字符串化，需要 *套一层转发宏* ：

#+begin_src c
#define VERSION 2.0
#define RAW_STR(x) #x
#define STR(x) RAW_STR(x)

// RAW_STR(VERSION) -> "VERSION"
// STR(VERSION)     -> 先展开为 2.0，再变成 "2.0"
#+end_src

** 常见用途

- *打印调试信息或断言条件* ：把表达式原封不动地打出来，方便排查问题。
- *生成配置项或字段名* ：减少重复手写字符串带来的拼写错误。
- *相邻字符串自动拼接* ：C/C++ 中紧挨着的字符串字面量会自动拼成一个，常用来拼前缀或后缀。

** 注意细节

- *多余空白会被压缩* ：参数中间的多个空格或 Tab，通常会折叠成单个空格；首尾多余空格会被去掉。
- *引号和反斜杠会自动转义* ：如果参数里带 ="= 或 =\= ，预处理后会自动加上 =\= 转义，保证合法的字符串字面量。

* 转发宏的技术实现原理

*转发宏（两层宏展开）的核心原理，是利用 C/C++ 预处理器对宏参数的“先完全展开、再替换”的扫描规则，避开 =#= 和 =##= 运算符阻止参数提前展开的特例。*

** 预处理器展开宏的标准顺序

当预处理器遇到一个普通的宏调用 =OUTER(arg)= 时，标准流程分三步走：

1. *检查实参* ：查看实参 =arg= 里是否包含其他宏。
2. *完全展开实参* ：如果 =arg= 是宏，先把它 *彻底展开* 成最终文本。
3. *代入并扫描* ：把展开后的结果塞进 =OUTER= 的替换列表里，再对整个结果重新扫描一遍。

** 为什么直接用 =#= 会失效？

C/C++ 标准给这条规则加了一个 *强制例外* ：
- 在替换列表里，只要某个形参前面紧挨着 =#= （字符串化）或 =##= （记号拼接），第 2 步就会被 *直接跳过* 。
- 预处理器会原封不动地把实参的原始记号拿去字符串化或拼接，根本不展开它。

** 转发宏如何绕过限制？

通过多包一层外层宏，我们把“展开参数”和“执行 =#= ”拆成了两个独立阶段：

#+begin_src c
#define VERSION 2.0
#define INNER(x) #x
#define OUTER(x) INNER(x)
#+end_src

以 =OUTER(VERSION)= 为例，逐步拆解：

1. *进入外层宏 =OUTER(VERSION)=* ： =OUTER= 的定义体是 =INNER(x)= ，里面的 =x= 前面 *没有* =#= 或 =##= 。
2. *触发常规展开* ：预处理器按标准流程，先把实参 =VERSION= 完全展开成 =2.0= 。
3. *完成外层替换* ： =OUTER(VERSION)= 变成了 =INNER(2.0)= 。
4. *重新扫描并进入内层宏* ：预处理器接着展开 =INNER(2.0)= 。此时传给 =INNER= 的实参已经是展开后的 =2.0= 了，最终得到 ="2.0"= 。

** 延伸：什么时候两层也不够？

- *宏内部调用自己（递归抑制）* ：如果展开过程中又遇到了正在展开的同一个宏，预处理器会把它标记为“不可再展开”，防止死循环。
- *拼接产生新宏名* ：如果内层用 =##= 拼出了一个新的宏名字，它会在下一步重新扫描时继续展开；但如果是 *在拼接之前* 需要展开左右两边的参数，同样需要靠外层转发宏先展开参数，再交给内层拼接。

* 拓展

除了利用两层宏绕开 =#= 和 =##= 的展开限制外，C/C++ 预处理中还有一套经典的 *高阶宏转发(预处理指令元编程)技巧* ，核心目的都是控制展开时机、分发参数或突破预处理器的递归限制:

1. *参数个数分发(宏重载/Variadic Dispatch)*: 使用 =__VA_ARGS__= 计算传入的参数个数，把调用自动转发给不同的宏，实现类似函数重载的效果:
   #+begin_src c
     // 1. 辅助第N个参数
     #define GET_MACRO(_1, _2, _3, NAME, ...) NAME

     // 2. 根据参数个数转发到具体的实现
     #define LOG(...) GET_MACRO(__VA_ARGS__, LOG3, LOG2, LOG1)(__VA_ARGS__)

     #define LOG1(a)       printf("%s", a)
     #define LOG2(a, b)    printf("%s: %d\n", a, b)
     #define LOG3(a, b, c) printf("%s: %d (%s)\n", a, b, c)
   #+end_src
