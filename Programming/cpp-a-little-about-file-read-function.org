** 助手

这个函数 =readTextFile= 的作用是把指定路径的文件完整读入内存，并以 =std::string= 的形式返回文件内容。

*它的主要执行步骤如下：*

*** 1. 打开文件

#+begin_src cpp
std::ifstream file(path, std::ios::binary);
#+end_src

这里创建了一个输入文件流对象 =file=，并以二进制模式（=std::ios::binary=）打开 =path= 指向的文件。二进制模式会关闭换行符等文本转换（例如 Windows 上的 =\r\n= 与 =\n= 的转换），因此读到的字节与磁盘上的完全一致。对于着色器源码这类文本，这通常是合适的，也避免了平台差异。

*** 2. 检查打开是否成功

#+begin_src cpp
if (!file) {
    throw std::runtime_error(std::string("Unable to read shader file: ") + path);
}
#+end_src

=!file= 会检查流的状态，如果文件不存在、没有读取权限等原因导致打开失败，就抛出 =std::runtime_error= 异常，并附上包含文件路径的错误信息，方便调用者排查问题。

*** 3. 读取全部内容

#+begin_src cpp
return {std::istreambuf_iterator<char>(file),
        std::istreambuf_iterator<char>()};
#+end_src

这是最核心的部分：

- =std::istreambuf_iterator<char>(file)= 是一个指向文件流底层字节缓冲区的迭代器，指向文件开头。
- =std::istreambuf_iterator<char>()= 是默认构造的迭代器，充当"结束标记"（end-of-stream）。
- 用这两个迭代器构造 =std::string=，就会逐个字节读取，直到文件末尾，把所有字符拼接成一个字符串。

返回值使用花括号初始化列表，会调用 =std::string= 的迭代器范围构造函数，因此不需要手动循环或预先知道文件大小。

*** 需要注意的几点

- *性能*：逐字节迭代虽然写法简洁，但比一次性 =read= 大块数据要慢。对于普通大小的着色器文件影响不大，但若要处理很大的文件，可以先用 =seekg=/=tellg= 获取文件大小，再用 =read= 一次性读入。
- *异常安全*：函数内部没有对读取错误做额外检查。如果在读取过程中出现 I/O 错误，它只会返回已读到的部分内容，不会报错。
- *返回值优化*：=return= 返回的是局部对象，现代 C++ 中会通过移动语义或返回值优化（RVO）避免额外拷贝。

*** 总结

这是一个简洁的文件读取工具函数：打开文件失败时抛出带路径信息的异常，成功时把整个文件内容作为字符串返回。在图形编程中，它常用于加载 GLSL/HLSL 等着色器源文件。

#+begin_src cpp
#include <fstream>
#include <stdexcept>
#include <string>

std::string readTextFile(const std::string &path) {
    std::ifstream file(path, std::ios::binary);
    if (!file) {
        throw std::runtime_error("Unable to read shader file: " + path);
    }

    // 获取文件大小
    file.seekg(0, std::ios::end);
    const std::streamoff size = file.tellg();
    if (size < 0) {
        throw std::runtime_error("Unable to determine size of shader file: " + path);
    }
    file.seekg(0, std::ios::beg);

    // 一次性分配空间并读取
    std::string content(static_cast<std::size_t>(size), '\0');
    if (size > 0 && !file.read(content.data(), size)) {
        throw std::runtime_error("Failed to read shader file: " + path);
    }

    return content;
}
#+end_src

*** 主要改进点

*1. 参数改为 =const std::string &=*
原版的 =const char *= 无法直接传入 =std::string=，调用方需要 =.c_str()=。改为 =std::string= 后，=const char*= 和 =std::string= 都能传入，因为前者会隐式转换。

*2. 检查读取是否成功*
原版只检查打开是否成功。读取过程中如果发生 I/O 错误，它会静默返回不完整的内容，这在着色器加载中很难排查。改进后，=file.read= 失败时会直接抛出异常。

*3. 预先获取文件大小，避免逐字节迭代*
用 =seekg= 和 =tellg= 获取大小后，只分配一次内存，再用 =read= 整块读入，性能明显优于 =istreambuf_iterator= 的逐字节读取。=tellg()= 失败时返回 -1，所以代码对此做了检查。

*4. 处理空文件*
当 =size == 0= 时跳过 =read= 调用，避免对空字符串取 =data()= 后进行无意义的读取。

*** 可选的进一步优化

如果项目使用 C++17 或更高版本，可以用 =std::filesystem::file_size= 获取大小，代码会更直观：

*** std::ifstream

=std::ifstream=（input file stream）是 =std::istream= 的派生类，专门用于从文件读取数据。它的构造函数接收文件路径和可选的打开模式：

#+begin_src cpp
std::ifstream file(path, std::ios::binary);
#+end_src

它有两个重要特性：

- *RAII 管理资源*：对象创建时打开文件，离开作用域时自动关闭文件，不需要手动调用 =close()=。即使函数中途抛出异常，文件也会被正确关闭。
- *可用于条件判断*：=!file= 之所以有效，是因为流对象重载了布尔转换。如果打开失败或之前的操作出错，它会返回 =false= 的等价值。

如果需要显式检查，可以写成 =if (!file.is_open())=，两者在这里的效果基本相同。

-----

*** std::ios::binary

=std::ios::binary= 是打开模式的一个标志，写在构造函数或 =open()= 的第二个参数中。多个标志可以用按位或 =|= 组合，例如 =std::ios::in | std::ios::binary=。

- *文本模式*（默认）：在某些平台（如 Windows）上，读取时会把 =\r\n= 转换为 =\n=，写入时则反向转换。
- *二进制模式*：不做任何转换，读到的字节与磁盘上的完全一致。

对于着色器源码，二进制模式可以确保读取内容和文件内容逐字节一致，避免跨平台差异。另外，=seekg= 和 =tellg= 返回的偏移量在二进制模式下与实际字节数一一对应，计算文件大小时更可靠。

-----

*** std::streamoff

=std::streamoff= 是一个*有符号整数类型*，通常是 =long long= 的别名，用来表示流中的偏移量。

#+begin_src cpp
const std::streamoff size = file.tellg();
#+end_src

它与 =std::streamsize= 的区别在于：

- =std::streamoff= 表示*位置或偏移*，可以是负数（例如相对当前位置向后移动）。
- =std::streamsize= 表示*字符数量*，例如 =read= 要读取的字节数。

使用有符号类型的好处是，=tellg()= 失败时会返回 =-1=，代码可以直接用 =if (size < 0)= 判断错误。如果用无符号类型，=-1= 就会变成一个很大的正数，错误很难被发现。

-----

*** std::ios::beg 与 std::ios::end

这两个常量属于 =std::ios_base::seekdir= 类型，用来指定 =seekg= 的*参照基准*：

| 常量 | 含义 |
|---|---|
| =std::ios::beg= | 从文件*开头*计算偏移 |
| =std::ios::cur= | 从*当前位置*计算偏移 |
| =std::ios::end= | 从文件*末尾*计算偏移 |

#+begin_src cpp
file.seekg(0, std::ios::end);   // 移动到文件末尾，偏移量为 0
file.seekg(0, std::ios::beg);   // 移动回文件开头
#+end_src

第一行中，=0= 的意思是"末尾位置加 0 字节"，也就是正好到达末尾。

*** seekg() 与 tellg()

这两个函数名中，=g= 表示 *get*，即输入（读取）指针。与之对应的是 =seekp= 和 =tellp=，操作的是输出（写入）指针。

**** seekg()

=seekg= 用于移动读指针，有两种形式：

#+begin_src cpp
file.seekg(pos);                  // 绝对定位：移动到第 pos 个字节
file.seekg(offset, std::ios::beg); // 相对定位：从基准位置偏移 offset 字节
#+end_src

改进后的代码使用了第二种形式，配合 =std::ios::end= 和 =std::ios::beg= 来获取文件大小。

**** tellg()

=tellg= 返回当前读指针的位置，类型为 =std::streamoff=。如果流处于错误状态，它会返回 =-1=。

**** 组合使用获取文件大小

#+begin_src cpp
file.seekg(0, std::ios::end);          // 1. 指针移到末尾
const std::streamoff size = file.tellg(); // 2. 末尾的位置就是文件大小
file.seekg(0, std::ios::beg);          // 3. 指针移回开头，准备读取
#+end_src

这个过程的原理是：文件末尾的偏移量恰好等于文件的字节数。读取前必须把指针移回开头，否则 =read= 会从末尾开始读，什么也读不到。

**** 基本用法

#+begin_src cpp
throw std::runtime_error("Unable to read shader file: " + path);
#+end_src

构造函数接收一个 =std::string= 或 =const char*= 作为错误信息，之后可以通过 =what()= 获取。

**** 捕获异常

#+begin_src cpp
try {
    std::string src = readTextFile("shader.vert");
} catch (const std::exception &e) {
    std::cerr << e.what() << std::endl;
}

由于 =std::runtime_error= 继承自 =std::exception=，因此可以用 =catch (const std::exception &)= 统一捕获。这里使用 =const &= 引用捕获，可以避免不必要的拷贝，也不会产生切片问题。

*** 1. ifstream 的缓冲区与自动关闭

*基本理解是对的，但有两点需要修正：缓冲区不是整个文件，而且 =std::ios::binary= 不决定是否有缓冲区。*

实际的过程大致如下：

- *=std::ifstream= 内部有一个缓冲区对象（=std::filebuf=）*，它的大小由标准库实现决定，通常是几 KB 到几十 KB，远小于整个文件。
- *文件数据不会一次性全部读入这个缓冲区。* 缓冲区是按需填充的：程序读数据时，缓冲区为空就从操作系统读一块数据进来，读完再读下一块。
- *=std::ios::binary= 只影响数据的"翻译"方式*，即是否做换行符转换。无论是否加这个标志，都会使用缓冲区。
- *=file.read(content.data(), size)= 的实际过程*：数据从操作系统经缓冲区被拷贝到 =content= 的内存中。对于较大的读取，标准库实现可能会绕过缓冲区直接读入目标内存，以提高效率。

所以更准确的描述是：文件内容经由流的缓冲区，被一块一块地拷贝到 =content= 中，缓冲区本身只是中转站。

*关于自动关闭：是的，不需要手动调用 =close()=。* =std::ifstream= 的析构函数会关闭文件并释放缓冲区。当 =file= 离开作用域（例如 =readTextFile= 函数返回或因异常退出）时，析构函数自动执行。这就是 RAII（资源获取即初始化）的做法。如果你想提前关闭，才需要手动调用 =file.close()=。

-----

*** 2. seekg 与 tellg 如何得到文件大小

*你的理解基本正确，但需要修正一个细节：=seekg= 并不是"插入标记"，而是改变流的读取位置。* 可以把它想象成一个指向文件字节的指针（或光标），=seekg= 就是移动这个光标。

具体过程如下：

1. *=file.seekg(0, std::ios::end);=*：把读取位置移动到"文件末尾 + 0 字节"，也就是最后一个字节之后的位置。
2. *=file.tellg()=*：返回当前读取位置相对于文件开头的偏移量。此时光标正在文件末尾，所以返回的偏移量就是*文件总字节数*。

打个比方：文件是一条从 0 开始编号的字节"尺子"。把光标移到尺子最末端，然后读出它的刻度，这个刻度就是尺子的长度。=tellg()= 并不需要自己计算大小，它只是报告光标的当前刻度。

因此，=seekg(0, std::ios::end)= 之后直接调用 =tellg()= 是正确的，中间不需要额外的步骤。最后再用 =seekg(0, std::ios::beg)= 把光标移回开头，才能从头读取内容。

*补充：* 在二进制模式下，这个刻度与实际字节数一一对应，因此结果可靠。这也是前面选择 =std::ios::binary= 的原因之一。

** 助手

下面的程序先用 =seekg= 和 =tellg= 获取并打印文件大小，然后用 =try/catch= 处理打开失败的情况。程序通过命令行参数接收文件路径。

#+begin_src cpp
#include <fstream>
#include <iostream>
#include <stdexcept>
#include <string>

// 使用 seekg/tellg 获取文件大小（字节数）
std::streamoff getFileSize(const std::string &path) {
    std::ifstream file(path, std::ios::binary);
    if (!file) {
        throw std::runtime_error("无法打开文件: " + path);
    }

    file.seekg(0, std::ios::end);          // 指针移到文件末尾
    const std::streamoff size = file.tellg(); // 末尾位置即文件大小
    if (size < 0) {
        throw std::runtime_error("无法获取文件大小: " + path);
    }

    return size;
    // file 在此析构，文件自动关闭
}

int main(int argc, char *argv[]) {
    if (argc < 2) {
        std::cerr << "用法: " << argv[0] << " <文件路径>" << std::endl;
        return 1;
    }

    try {
        const std::streamoff size = getFileSize(argv[1]);
        std::cout << "文件大小: " << size << " 字节" << std::endl;
    } catch (const std::exception &e) {
        std::cerr << "错误: " << e.what() << std::endl;
        return 1;
    }

    return 0;
}
#+end_src
