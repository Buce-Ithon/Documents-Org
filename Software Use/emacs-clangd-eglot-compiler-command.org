#+TITLE: clangd Compiler Command Selection in Eglot (Why .h Headers Are Simply Parsed as C)
#+AUTHOR: Buce-Ithon
#+DATE: [2026-11-13 周五]

* Background
When Emacs connects to *clangd* through *Eglot*, clangd must decide which
compiler command to use for every file it analyses. For a new header without
a compilation database entry, that decision can silently fall back to a
*C compile command*, even when the project is C++.

This note records a real case in
=D:/Projects/animation-class-cpp/examples/cautio/=, the diagnosis, and the verified fixes.

* Symptoms
Opening =./template/file_helper.h= in Emacs produced:

#+begin_example
clangd [unused-includes]: Included header cstdio is not used directly (fixes available)
clang [pp_hash_error]: In included file: error STL1003: Unexpected compiler, expected C++ compiler.
#+end_example

- =STL1003= comes from the *MSVC STL* (=<yvals_core.h>=): it is raised when the
  header is compiled as *C*, i.e. =__cplusplus= is not defined.
- =unused-includes= is only a clangd style hint, not an error.
- The file itself was incomplete (a bare =const= with no name), but that was
  unrelated to the language-mode failure.

* How clangd Chooses a Compile Command
clangd resolves the compile command for a file in this order:

1. ~compile_commands.json~ entry that matches the file.
2. ~compile_flags.txt~: searched from the file's directory upwards; the first
   one found wins. Treat this as a per-directory database.
3. ~Inference~: if the file is not in the database, clangd borrows the compile
   command of another source file in the project (the nearest one it can find)
   and adapts the language flags.
4. Built-in fallback command.

In this project:

- =compile_commands.json= (generated by CMake in the build directory and copied
  to the project root) contains only =src/main.cpp= and =ext/glad/src/glad.c=.
- =template/= files are *not* part of the build, so rule 2 did not apply
  (no =compile_flags.txt= existed) and clangd used rule 3.

* Root Cause
clangd inferred the command from a *C* source file:

#+begin_example
Compile command inferred from .../ext/glad/src/glad.c is:
  clang.exe ... -c -x c-header -std=gnu11 -- .../template/file_helper.h
#+end_example

Because of =-x c-header -std=gnu11=, the header was parsed as C. Including
=<cstdio>= then pulled in the MSVC STL, which refuses non-C++ compilers:

#+begin_example
error STL1003: Unexpected compiler, expected C++ compiler.
#+end_example

Note that clang itself was targeting the right ABI all along
(=x86_64-pc-windows-msvc19.44=); only the *language* was wrong.

* Diagnosing with =clangd --check=
=--check= is clangd's batch self-diagnosis mode. It reproduces exactly what the
language server does for a file, but prints its internal resolution log:

#+begin_src shell
clangd --check=template/file_helper.h
#+end_src

Useful lines to look for:

#+begin_example
I[...] Compile command inferred from .../glad.c is: ...
I[...] Compile command from CDB is: ...
I[...] internal (cc1) args are: -cc1 ... -x c-header ...
E[...] [pp_hash_error] ... STL1003 ...
I[...] All checks completed, 6 errors
#+end_example

* Verified Fixes
** Option A: =template/compile_flags.txt= (used)
Create a file named =compile_flags.txt= next to the headers, one argument per
line:

#+begin_src
-x
c++-header
-std=c++17
#+end_src

Result:

#+begin_example
Compile command from CDB is:
  clang-tool -x c++-header -std=c++17 -- .../template/file_helper.h
All checks completed, 2 errors        (only the incomplete code remains)
#+end_example

Caveats:

- It applies to *every* file in that directory. A future =.cpp= in =template/=
  would also be parsed with =-x c++-header=, which is wrong.
- A =compile_flags.txt= in the *project root* does not help: it sits next to
  =compile_commands.json=, and the compilation database takes precedence there.
  Place it in a directory that has no database of its own.

** Option B: use a C++ header extension
Renaming to =file_helper.hpp= (or =.hh= / =.hxx=) needs *no configuration at
all*. Verified: clangd then inferred the command from =src/main.cpp= and
applied =-x c++-header= automatically.

#+begin_example
Compile command inferred from .../src/main.cpp is:
  clang++.exe --driver-mode=g++ ... -std=gnu++17 ... -x c++-header
#+end_example

** Option C: project-level =.clangd=
One config file at the project root, scoped with =PathMatch= (verified):

#+begin_src yaml
If:
  PathMatch: template/.*\.h
CompileFlags:
  Add: [-x, c++-header, -std=c++17]
#+end_src

The resulting command contains both =... -x c-header ... -x c++-header ...=;
the *last* =-x= wins, so the file is parsed as C++. More flexible than
=compile_flags.txt= (can target patterns and adjust diagnostics), but it
affects every clangd session in the project.

** Not recommended: editing =compile_commands.json=
CMake regenerates the file on every build, so hand-written entries are lost.

* Seeing clangd's Decisions Inside Emacs
Eglot only forwards LSP *diagnostics*; the "Compile command inferred ..." log
lives on clangd's stderr and does not appear in the buffer automatically.

- =M-x eglot-events-buffer= :: shows the server's stderr log stream.
- Add =--log=verbose= for much more detail, e.g.:

#+begin_src emacs-lisp
(setq eglot-server-programs
      '(((c++-mode c-mode c++-ts-mode c-ts-mode)
         ("clangd" "--log=verbose"))))
#+end_src

  Then =M-x eglot-reconnect=. clangd picks up configuration changes such as a
  new =compile_flags.txt= automatically, but reconnecting is the safe way.

* Extra Notes
- To silence the harmless =unused-includes= hint project-wide, add a
  =.clangd= file:

#+begin_src yaml
Diagnostics:
  UnusedIncludes: None
#+end_src

- Environment used for the diagnosis:
  - clangd 23.1.4 (=x86_64-pc-windows-msvc=)
  - MSVC 14.44 toolchain and Windows SDK 10.0.22621 headers
  - Project compiled with clang++ targeting the MSVC ABI (see the GLFW
    library selection issue in the same project).

* Summary
- clangd needs a reason to treat a =.h= file as C++; without a database entry
  it may borrow a *C* command from a nearby file.
- Provide one of: C++ header extension, =compile_flags.txt= in the header's
  directory, or a =.clangd= =PathMatch= rule.
- Use =clangd --check=<file>= to see exactly which command clangd chose and why.
- Eglot's =eglot-events-buffer= is the in-editor view of the same information.
